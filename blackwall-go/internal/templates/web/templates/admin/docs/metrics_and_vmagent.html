BlackWall exposes two metric surfaces: a Prometheus-compatible scrape endpoint, and an optional outbound push of every audit event as a counter sample.

/metrics scrape endpoint

Authenticated by bearer token (metrics_token in config.yaml) by default. Set metrics_allow_unauthenticated: true to drop the check — only do this if /metrics is otherwise network-isolated.

The endpoint emits gauges for: total user count, active user count, project count, active OAuth client count, registered WebAuthn credential count, audit events written today, active access tokens, and pending approval count.

Event push (vmagent / VictoriaMetrics)

If event_metrics_push_enabled: true and event_metrics_push_url is set, every audit event is also pushed asynchronously as a single counter sample to that URL. Format is Prometheus text exposition.

Config keyPurpose
event_metrics_push_metric_nameDefaults to blackwall_event.
event_metrics_push_include_outcomeAdds outcome="success|fail|info" label.
event_metrics_push_static_labelsComma-separated extra labels e.g. env="prod",region="eu-west".
event_metrics_push_timeout_msHTTP timeout per push, default 250ms. Pushes happen in goroutines so a slow endpoint doesn't block the audit write.
Validation
  1. Trigger a known event (e.g. open the dashboard).
  2. Watch vmagent's ingest log for the new sample.
  3. Query blackwall_event{event_type="oauth.authorize.begin"} in your dashboard tool and confirm a new sample arrives.

If the push silently fails, the audit row still lands in audit_log — there is no inline retry queue. If you need lossless metric delivery, scrape /metrics instead.
