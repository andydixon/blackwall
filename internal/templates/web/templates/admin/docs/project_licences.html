Project licences are Ed25519-signed entitlement statements for a legal person or business. They are separate from OAuth clients and are managed from Projects → project → Licences.

What is signed
  • Version, licence UUID, fixed issuer and audience, and project UUID.
  • Entity type, legal name, and an optional non-secret customer or company reference.
  • One to 32 exact hostnames, optional feature identifiers, and a maximum instance count.
  • Issue, not-before, and expiry timestamps; key ID; status URL; and maximum online-check interval.

Wildcard hostnames are deliberately unsupported. Enter every DNS name or IP literal explicitly. Use ASCII punycode for international DNS names; do not enter a URL, scheme, port, path, user information, or secret.

Roles and audit
  • super_admin has view_licences and manage_licences: issue, download, and permanently revoke.
  • operator has scoped view_licences: inspect and download, but cannot sign or revoke.
  • auditor has neither project-licence capability.

Issue, failed issue, and revoke events are audited. Entity names, references, and licence bodies are intentionally excluded from audit metadata.

Signing-key setup
umask 077
openssl genpkey -algorithm Ed25519 \
  -out /run/secrets/blackwall_licence_ed25519.pem
chmod 0600 /run/secrets/blackwall_licence_ed25519.pem

Set licence_signing_key_file to that mounted path and restart. The file must contain one Ed25519 PKCS#8 PRIVATE KEY PEM block and be mode 0600 or stricter. Blackwall stores public keys only. Never put the private key in Git, an image, an environment variable, MySQL, an audit event, or a shared volume.

Verification and revocation

A valid signature prevents claim editing, but offline verification cannot see a subsequent revocation. Integrations should call the fixed HTTPS status_url at least every signed online_check_seconds and fail closed when the result is unavailable or non-valid.

  • GET /.well-known/blackwall-licence-keys.json publishes Ed25519 public keys, fingerprints, and key status.
  • POST /licences/v1/verify checks signature, key state, exact signed bytes in MySQL, project state, revocation, issuer, project, exact hostname, and time.

The source distribution includes the normative docs/licensing/VERIFYING_LICENCES.md guide and fail-closed PHP, Go, Rust, and Java examples.

Rotation and compromise

Replace the mounted private key and restart to activate a new key and retire the previous one. Retired public keys remain available so existing licences verify. If a key may have leaked, stop issuance, mark it compromised, install a new key, revoke and reissue the affected licences, and force consumers to refresh the key registry. Blackwall refuses to reactivate a compromised key.
