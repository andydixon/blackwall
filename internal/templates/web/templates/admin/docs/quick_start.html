This walks through what to do in your first session as a freshly-bootstrapped super-admin.

1. Verify your own credential

Sign out and sign back in. If WebAuthn doesn't recognise your passkey, your enrolment didn't take — re-bootstrap with a fresh enrolment link before doing anything else.

2. Confirm the audit chain is being written

Open /admin/audit and look for entries from the last few minutes. Each entry carries a chain_hash; if those are blank, audit writes are failing — stop and fix the database connection before continuing.

3. Create the first additional organisation

Even if everything will live in one org, create a second one early so you exercise the multi-tenant code paths during testing.

4. Enrol an operator

Create a new user, hand them the one-shot enrolment link, then assign them the operator admin role. Confirm they can sign in but cannot perform delete_credentials_direct actions — that's correct, those go through approval.

5. Register a test OAuth client

Register an OIDC-enabled confidential client against any project and run an authorisation-code+PKCE flow from your preferred client. Include max_age=0 for the test, complete the passkey prompt, and confirm the ID token contains matching nonce, at_hash, and numeric auth_time claims.

6. Trigger maintenance

Open /admin/maintenance and run the scheduled jobs once manually. Verify all jobs land at success with non-zero rows_affected on a populated database.

Safety checks before going live
  • HSTS header is being emitted (over HTTPS only).
  • CryptBin KEK is configured (server refuses to handle CryptBin requests without it).
  • Rate limiting is enabled in config.yaml.
  • Backup of the MySQL database is scheduled — see the Maintenance & DR page.
