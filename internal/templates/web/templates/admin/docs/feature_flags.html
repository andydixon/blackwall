Each project carries an independent set of feature toggles that govern which enterprise surfaces apply. New projects start with the modern defaults turned on; projects that existed before the v3 schema migration start with everything off, so upgrading BlackWall never silently changes behaviour for an in-flight tenant.

Where to edit

Open /admin/projects/{uuid} → Feature flags card. Requires manage_projects.

The flags
webhooks_enabled
Gate the outbound webhook dispatcher. Registered endpoints can still be edited while off; nothing gets delivered until on. See Webhooks.
db_sessions_enabled
Records each authenticated session in the user_sessions table so it can be revoked server-side. With this off, only the cookie's natural expiry ends a session. See Server-Backed Sessions.
max_concurrent_sessions
When > 0 and DB sessions are on, capping a user to N parallel sessions across this project. A login that would exceed N revokes the oldest session first. 0 means unbounded.
custom_branding_enabled
Pull the organisation's branding overlay onto login screens served for this project. See Branding and Custom Domains.
step_up_required
Reserved for the upcoming step-up auth surface (force a fresh WebAuthn touch for high-impact actions). Off by default; turning it on without the step-up surface in place is a no-op.
