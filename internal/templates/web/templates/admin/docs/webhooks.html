BlackWall fans every project-scoped audit event out to registered webhook receivers. The dispatcher runs in the background; the originating HTTP request never blocks on a downstream callout.

Where to manage them

Open /admin/projects/{uuid}/webhooks. Requires view_projects to see, manage_projects to register / edit / delete. The project's webhooks_enabled feature flag must be on for the dispatcher to deliver — see Feature flags.

Delivery contract
  • Method & encoding: POST with Content-Type: application/json.
  • Signature header: X-BlackWall-Signature: t=<unix-ts>,v1=<hex> where hex = HMAC-SHA256(secret, ts + "." + body).
  • Event identification: X-BlackWall-Event (event type) and X-BlackWall-Event-Id (UUID, stable across retries).
  • Payload envelope: { id, type, project_id, occurred_at, data, api_version: "2024-11" }.
Verifying signatures (receiver side)
# Pseudocode — every language's HMAC is the same shape.
sig_header = request.headers["X-BlackWall-Signature"]
ts         = parse "t=" from sig_header
v1         = parse "v1=" from sig_header
expected   = hmac_sha256(secret, ts + "." + raw_body).hex
if not constant_time_equal(v1, expected): reject
if abs(now() - ts) > 5 minutes:           reject  # optional replay window
Retry & backoff

Failed deliveries (transport error or non-2xx) re-queue with an exponential backoff: 30s → 5m → 30m → 6h → 24h, capped at 5 attempts before the row is marked exhausted. After 20 consecutive failures the endpoint is auto-disabled so we stop hammering a dead receiver — the admin sees the disabled badge and can investigate, fix, and re-enable.

Inspecting deliveries

Each endpoint has a Deliveries link showing the last 100 attempts with status code, attempt count, and a 512-byte excerpt of the response body. Use this for debugging without log scraping.

Audit events suitable for webhooks

Any event the audit logger writes with a project_id is delivered. Common ones to consume:

  • admin.user.create, admin.user.update, admin.user.status.change
  • portal.login.success, portal.login.fail
  • oidc.userinfo.success
  • admin.client.create, admin.client.update
  • Custom-claim mutations: admin.claims.user.upsert, admin.claims.project_default.upsert

Use the per-endpoint Events filter (comma-separated) to subscribe to a subset, or * for everything.

Secret rotation

Click Rotate on an endpoint to mint a new secret. The new value is shown ONCE; copy it before navigating away. The old secret stops working immediately.
