Users in BlackWall have no passwords. They authenticate exclusively with WebAuthn (passkeys), and they're created in two stages: profile first, then a one-time enrolment link the user follows to register their first credential.

Lifecycle
  1. Operator fills /admin/users/create: display label, optional email, organisation, status.
  2. BlackWall generates a 32-byte enrolment token, valid for 24 hours, stored in system_config.
  3. Operator copies the enrolment URL from the user's detail page and sends it out-of-band (email, signal, etc.).
  4. The user opens the URL in a WebAuthn-capable browser and registers their authenticator.
  5. From that point on, the user can sign into the portal at /portal/login and any OAuth client whose project they're assigned to.
Status meanings
  • active — can sign in, holds tokens, appears in /portal.
  • inactive — cannot sign in; existing tokens still work until they expire (use revocation if you need immediate effect).
  • suspended — cannot sign in; existing tokens are rejected at validation time.
WebAuthn credentials

Each user can register multiple authenticators. Sign-counter regression is treated as a cloned-credential indicator and the assertion is rejected. Both the User Present (UP) and User Verification (UV) flags are required at every assertion.

When a user loses their authenticator
  1. Operator opens the user's detail page.
  2. Operator deletes the lost credential. (operator role: this enqueues an approval; super_admin applies it directly.)
  3. Operator generates a fresh enrolment link from the same page and sends it to the user.
  4. User registers a replacement credential and they're back in.
Removing access permanently

Set the user to suspended. Existing access tokens stop being honoured at the next userinfo / introspect call. To purge all credentials, delete each one from the user detail page; the user record itself is preserved so audit history remains attributable.
