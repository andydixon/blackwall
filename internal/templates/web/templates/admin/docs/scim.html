SCIM 2.0 (RFC 7643 + RFC 7644) is the standard upstream identity providers (Workday, Okta, Entra ID, BambooHR, Rippling, Google Workspace, …) use to push user-lifecycle changes into downstream apps. BlackWall exposes /scim/v2/Users so any of these can provision, update, and deprovision users without an operator copying them by hand.

Base URL and authentication
  • Base URL: https://<your-blackwall>/scim/v2
  • Auth: Authorization: Bearer bw_admin_... (see Admin API Tokens).
  • Target project: X-BlackWall-Project: <project-uuid> — every SCIM operation is scoped to one project; this is the project users get assigned to on create.
Endpoints implemented
Method & pathBehaviour
GET /UsersList with optional filter, startIndex, count.
POST /UsersCreate. Conflict on duplicate externalId.
GET /Users/{id}Read by user UUID.
PUT /Users/{id}Full replace.
PATCH /Users/{id}Operations array (replace, add).
DELETE /Users/{id}Deactivates — does not hard-delete.
GET /ServiceProviderConfigCapability discovery.
GET /ResourceTypesLists supported resource types (currently just User).
GET /SchemasLists supported schemas.
Filter operators supported
  • eq — exact match. userName eq "alice@example.com"
  • sw — starts with. userName sw "alice"
  • co — contains. userName co "@example.com"
  • pr — present (non-null, non-empty). externalId pr
  • and joins clauses.

Filterable attributes: userName, externalId, id, active. Disjunction (or) and bracketed grouping are not yet supported — every IdP we surveyed only emits conjunctions.

Why DELETE doesn't delete

A runaway HRIS connector that bulk-fires DELETE shouldn't be able to wipe an organisation's identity store. DELETE /Users/{id} sets the user's status to disabled — the row, audit lineage, and credentials remain. To actually remove a user, do it from the admin UI with the approval workflow.

External ID mapping

Most IdPs identify users by their own ID space, not your UUID. We round-trip that via the externalId field — on create, we map (project, externalId) → user. Subsequent PUT/PATCH from the same IdP can address the user by either id (your UUID) or externalId.

Audit

Every SCIM mutation logs as scim.user.create, scim.user.replace, scim.user.patch, or scim.user.deactivate, with actor_user_id set to the token owner.
