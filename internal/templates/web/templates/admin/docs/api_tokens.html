Admin API tokens are bearer credentials for the JSON admin API at /api/v1/*, the SCIM 2.0 surface at /scim/v2/*, and the Terraform provider. Each token is bound to a specific user and inherits that user's admin capabilities at request time — there is no token-side capability escalation. Revoking a user's admin role takes effect for their tokens on the next request.

Where to manage them

Open /admin/api-tokens (super-admin nav link API tokens). Requires manage_roles.

Format and storage
  • Plaintext shape: bw_admin_<32 base64url chars>.
  • The full plaintext is shown once at creation. The server stores only a SHA-256 hash plus a 12-character prefix for UI identification.
  • Lost a token? Revoke and reissue — there is no recovery path.
Using a token
curl -H "Authorization: Bearer bw_admin_..." \
     https://auth.example.com/api/v1/projects
Expiry

Optional. Without an expiry, the token lives until manually revoked or until the owning user is deleted. For automation we recommend short-lived rotated tokens; for one-off admin scripts, no expiry is fine.

Scopes

The scopes field is currently advisory — a token with admin:full inherits the user's full admin capability set. Narrower scope strings (e.g. scim:read) are stored but not yet enforced at request time. Future versions will gate endpoints on declared scopes; choose conservative scopes today so a later upgrade doesn't unexpectedly tighten existing automations.

Audit

Every token mutation logs to the audit chain:

  • admin.token.create — actor, token public_id, scopes, optional expiry.
  • admin.token.revoke — actor, token public_id.

Every API request authenticated by a token contributes the actor user to the audit event for the underlying mutation — for example, a SCIM-driven user create logs scim.user.create with actor_user_id set to the token owner.
